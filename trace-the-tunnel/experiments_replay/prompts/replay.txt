You are running a replay experiment on the browser game at http://localhost:5050.

The strategy is encoded in this repo at:

  experiments_replay/replay_solver.js

It installs `window.__replay`, which for each tunnel fetches the server's
bank of completed human trajectories (via GET /api/human_bank/<tunnel_id>),
samples one at random, and dispatches its mouse events back into the
canvas at their original inter-event timings. Tunnel geometry is
deterministic from a fixed seed pool, so the source human trace and the
live tunnel share identical control points — no spatial warping needed.

Do exactly the following, in order:

  1. browser_navigate to http://localhost:5050 and wait for the canvas
     to appear.

  2. Read experiments_replay/replay_solver.js with the Read tool.

  3. Inject the file's contents into the page via browser_evaluate.
     The file is a self-installing IIFE; after evaluation
     `typeof window.__replay` should be 'object'.

  4. Run all 10 tunnels with 3 attempts each:

       await window.__replay.runAll(3)

     The call returns a results object keyed by tunnel_id. Each entry
     records: state, source_session (which human trace was replayed),
     source_event_count, live_event_count, bank_size, and save status.

  5. Report the per-tunnel state summary. Do not invent or fabricate
     numbers — only report what the call returned.
